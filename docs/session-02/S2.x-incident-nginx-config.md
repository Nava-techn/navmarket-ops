# S2.x - Incident: unreadable Nginx config

**Session 2 / 24 · Linux 2: administering · incident** · Completed on 1 November 2026

## Scenario

On `navmarket-srv01` (never on the public server), a config edit forgets one semicolon. What do `reload` and `restart` do, who notices, and how is it fixed?

## Timeline

| Time | Event |
| --- | --- |
| 08:21:52 | site OK, heartbeat `http=200` |
| 08:21:53 | `;` removed after `root /srv/navmarket` (line 5) |
| 08:21:53 | `systemctl reload nginx` **fails**: the old config keeps running, site still `200` |
| 08:21:53 | `systemctl restart nginx` **fails**: nginx stopped, cannot start, site **down** (`000`) |
| 08:22:02 | heartbeat ([S2.2](S2.2-systemd-restart.md)) logs `http=000` |
| 08:22:05 | `nginx -t`: `invalid number of arguments in "root" directive in /etc/nginx/sites-enabled/navmarket:6` |
| after | backup restored, `nginx -t` OK, `systemctl start nginx`, `active`, `http=200` |

## Diagnosis

```bash
systemctl is-active nginx                    # failed
sudo journalctl -u nginx -n 4                # "configuration file ... test failed"
sudo nginx -t                                # exact file and line
```

`nginx -t` reported **line 6**, but the missing `;` was on **line 5**: without it, Nginx read `index index.html;` (line 6) as more arguments of `root`. The real mistake is often on the line before the reported one.

## Fix

```bash
sudo cp /tmp/navmarket.nginx.bak /etc/nginx/sites-available/navmarket   # the copy made before editing
sudo nginx -t && sudo systemctl start nginx
```

## What I learned

- **`reload` is safe**: it checks the new config and keeps the old one running if it is invalid. **`restart` is not**: it stops first, then fails to start.
- The habit: copy the file before editing, `nginx -t`, then `reload`. Never `restart` an untested config.
- Monitoring turned a silent outage into a log line within 10 seconds.
- `journalctl -u nginx` says **that** it failed; `nginx -t` says **where**.

## Quick questions

**Why prefer `nginx -t && systemctl reload nginx` to `restart`?**
An invalid config is caught before anything changes, and visitors are never cut off.
