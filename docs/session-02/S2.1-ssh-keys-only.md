# S2.1 - SSH access with keys only

**Session 2 / 24 · Linux 2: administering** · Completed on 26 October 2026

## Goal

Nobody can log in to my servers with a password anymore, only with an SSH key. Password logins are what bots try all day on public servers.

**Done when:**

1. I log in to `navmarket-srv01` with a dedicated key, through a short `ssh srv01`;
2. a password login is refused on `navmarket-srv01` **and** `navmarket-vps01`;
3. `sshd -T` (the settings sshd really uses) shows the same rules on both servers.

## What I did

### 1. A key for srv01, installed once

```bash
ssh-keygen -t ed25519 -f ~/.ssh/navmarket_srv01 -C "navatech workstation to srv01"
ssh-copy-id -i ~/.ssh/navmarket_srv01.pub valdes@<VM_IP>   # last time the password is typed
```

`ssh-copy-id` adds the **public** key to `~/.ssh/authorized_keys` on the server. The private key never leaves my workstation. One key per server: if one leaks, I revoke only that one.

### 2. A shortcut in `~/.ssh/config`

```
Host srv01
    HostName <VM_IP>
    User valdes
    IdentityFile ~/.ssh/navmarket_srv01
```

### 3. Passwords off, with a drop-in file (same file on both servers)

`/etc/ssh/sshd_config.d/10-hardening.conf`:

```
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin no
PubkeyAuthentication yes
```

```bash
sudo sshd -t && sudo systemctl reload ssh    # test first, then reload; keep the current session open
```

- **Why `10-`:** sshd reads `sshd_config.d/*.conf` in alphabetical order and keeps the **first** value it finds. Ubuntu ships `50-cloud-init.conf` (srv01) and `60-cloudimg-settings.conf` (vps01); `10-` is read before them, so my rules win.
- `PermitRootLogin no`: Oracle's default was `without-password` (root by key only). Nobody needs root over SSH: I log in as a normal user and use `sudo`.

## Proof

Full outputs: [`S2.1-proofs.txt`](S2.1-proofs.txt) (IPs masked).

- `sshd -T` on **both** servers: `passwordauthentication no`, `kbdinteractiveauthentication no`, `permitrootlogin no`, `pubkeyauthentication yes`
- key login: `key login OK as valdes`
- password login on both: `Permission denied (publickey).`

## Problems and solutions

### `sudo: A terminal is required to authenticate` in the proof script

**Cause:** `ssh srv01 'sudo ...'` runs without a terminal, so sudo cannot ask for the password.
**Solution:** run the sudo part with `ssh -t` (a terminal is given), save the result to a file on the server, then read that file without sudo.

## What I learned

- A key pair: the server keeps the public key, I keep the private one; a passphrase protects the private key.
- `sshd -T` shows the **effective** settings; reading the config file is not a proof.
- Drop-in files are read in alphabetical order, and the first value wins.
- Always `sshd -t` before a reload, and keep a session open: a mistake can lock me out.
- `-o PubkeyAuthentication=no -o PreferredAuthentications=password` forces a password attempt, to prove it is refused.

## Quick questions

**Why disable password logins if my password is strong?**
Bots try passwords non-stop; with keys only, there is nothing to guess.
