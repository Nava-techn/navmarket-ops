# S2.3 - Nightly cron backup, 7 days kept

**Session 2 / 24 · Linux 2: administering** · Completed on 28 October 2026

## Goal

Every night, back up the storefront and its Nginx site on `navmarket-srv01`, and keep only the last 7 days, so the disk never fills up.

**Done when:**

1. a cron entry runs the backup every night;
2. one run creates a dated archive with the site **and** its Nginx config;
3. archives aged 7 days or more are deleted automatically, and the run is logged.

## What I did

### 1. The script

[`scripts/session-02/s2.3-navmarket-backup.sh`](../../scripts/session-02/s2.3-navmarket-backup.sh), installed in `/usr/local/bin/`:

```bash
tar -czf "$DEST/navmarket-$(date +%F_%H%M).tar.gz" -C / srv/navmarket etc/nginx/sites-available/navmarket
find "$DEST" -name 'navmarket-*.tar.gz' -mtime +6 -delete      # retention: 7 days
logger -t navmarket-backup "created ..., deleted N old archive(s)"
```

- `-C /`: relative paths in the archive (`srv/navmarket/...`), so it can be restored anywhere.
- `-mtime +6`: modified 7 full days ago or more.
- `set -euo pipefail`: the script stops at the first error instead of going on silently.
- Backup folder `/var/backups/navmarket` in mode `700`: root only.

### 2. The schedule

[`scripts/session-02/s2.3-navmarket-backup.cron`](../../scripts/session-02/s2.3-navmarket-backup.cron), installed as `/etc/cron.d/navmarket-backup` (mode 644):

```
# m  h  dom mon dow  user  command
30 2  *   *   *    root  /usr/local/bin/navmarket-backup.sh
```

Files in `/etc/cron.d/` have a **user** field, unlike a personal `crontab -e`.

### 3. Testing 7 days of retention in one minute

```bash
for d in $(seq 1 10); do sudo touch -d "$d days ago" /var/backups/navmarket/navmarket-test-$d-days.tar.gz; done
sudo /usr/local/bin/navmarket-backup.sh
```

`touch -d` gives fake archives an old date, so one run proves the retention.

## What I learned

- Cron syntax: minute, hour, day of month, month, day of week; `/etc/cron.d/` adds the user.
- A backup without retention fills the disk; `find -mtime +N -delete` is the classic rotation.
- `logger -t` writes to the system log, read with `journalctl -t <tag>`.
- Test time-based rules by changing file dates (`touch -d`) instead of waiting.
- A backup is only real if I can list (and restore) what is inside: `tar -tzf`.

## Quick questions

**Why put the date and time in the archive name?**
Archives sort by name in time order, and I can find the version from a given night at once.
