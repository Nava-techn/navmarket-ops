# S2.5 - Top IPs and 404s from the logs, in one command

**Session 2 / 24 · Linux 2: administering** · Completed on 30 October 2026

## Goal

From the real Nginx logs of `navmarket-vps01` (public since 21 October), find who visits the site and which missing pages are requested, with one pipeline each.

**Done when:** the top 10 client IPs and the top 10 URLs answered `404` come from one command each, over the current **and** rotated logs.

## What I did

[`scripts/logs/nginx-report.sh`](../../scripts/logs/nginx-report.sh) (run with `sudo`):

```bash
zcat -f $(ls -tr /var/log/nginx/access.log*) | awk '{print $1}' | sort | uniq -c | sort -rn | head -10              # top IPs
zcat -f $(ls -tr /var/log/nginx/access.log*) | awk '$9 == 404 {print $7}' | sort | uniq -c | sort -rn | head -10   # top 404 URLs
```

| Part | Role |
| --- | --- |
| `zcat -f ... access.log*` | current log + rotated ones (`.1`, `.N.gz`); `-f` also reads uncompressed files |
| `awk '{print $1}'` / `'$9 == 404 {print $7}'` | column 1 = client IP; column 9 = status, column 7 = URL |
| `sort \| uniq -c` | `uniq -c` counts **neighbouring** identical lines: sort first |
| `sort -rn \| head -10` | biggest counts first, keep 10 |

## Proof

Full outputs: [`S2.5-proofs.txt`](S2.5-proofs.txt). IPs masked as `a.b.x.x` (so two different IPs can look the same).

- 15 log files (about 2 weeks), **10,477 requests**
- status codes: **7,770 × 404**, 1,781 × 200, 273 × 405, 118 × 400
- top 404s: `/.env` (255), `/SDK/webLanguage` (186), `/.git/config` (37), `/.env.production`, `/.env.local`, `/.env.backup`
- top client: 1,372 requests from a single IP

## What I learned

- A public server is scanned from day one: **74 %** of the requests were bots looking for leaked secrets (`.env`, `.git/config`) or known vulnerable apps, not visitors.
- Nginx rotates its logs daily (`logrotate`) and compresses old ones: `zcat -f` reads them all.
- Some "status codes" are garbage (`\x16\x03...`): bots sending HTTPS or binary data to port 80, so the log line has no normal columns.
- `sort | uniq -c | sort -rn | head` is the universal "top N" in a shell.

## Quick questions

**Why must `sort` come before `uniq -c`?**
`uniq` only merges identical lines that are next to each other.
