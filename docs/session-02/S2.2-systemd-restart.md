# S2.2 - A systemd service that restarts on its own

**Session 2 / 24 · Linux 2: administering** · Completed on 26 October 2026

## Goal

Run a small monitoring service on `navmarket-srv01` that **comes back by itself** if it crashes or is killed, with no human action.

**Done when:**

1. the service starts at boot (`enabled`) and runs (`active`);
2. after a `kill -9`, systemd restarts it with a new PID;
3. its output is readable with `journalctl`.

## What I did

### 1. The service: a heartbeat for the storefront

[`scripts/heartbeat/navmarket-heartbeat.sh`](../../scripts/heartbeat/navmarket-heartbeat.sh) checks `http://localhost/` every 10 s and prints the HTTP code. Anything a service prints goes to the systemd journal.

### 2. The unit file

[`scripts/heartbeat/navmarket-heartbeat.service`](../../scripts/heartbeat/navmarket-heartbeat.service):

```ini
[Service]
ExecStart=/usr/local/bin/navmarket-heartbeat.sh
Restart=always        # restart whatever the reason it stopped
RestartSec=5          # wait 5 s: no restart storm on a permanent error
DynamicUser=yes       # a temporary unprivileged user, not root

[Install]
WantedBy=multi-user.target   # started at boot
```

```bash
sudo install -m 755 navmarket-heartbeat.sh /usr/local/bin/
sudo install -m 644 navmarket-heartbeat.service /etc/systemd/system/
sudo systemctl daemon-reload                       # systemd rereads its unit files
sudo systemctl enable --now navmarket-heartbeat    # start now and at every boot
```

### 3. The test: kill it

```bash
sudo kill -9 $(systemctl show -p MainPID --value navmarket-heartbeat)   # SIGKILL: cannot be caught
systemctl show -p NRestarts --value navmarket-heartbeat                 # 1
```

## Proof

Full outputs: [`S2.2-proofs.txt`](S2.2-proofs.txt).

- `enabled`, `active`; MainPID **3127** before the kill, **3421** after; `NRestarts: 1`
- journal: `Main process exited, code=killed, status=9/KILL` → `Scheduled restart job, restart counter is at 1` → `Started`
- after the incident fix below: `http=403` became `http=200`

## Problems and solutions

### The heartbeat found a real 403 on the storefront

**Symptom:** the first heartbeat lines said `http=403`. `error.log`: `"/srv/navmarket/index.html" is forbidden (13: Permission denied)`.

**Cause:** `namei -l` showed `drw-rwSr--` on `/srv/navmarket`: the folder had lost its **`x`** right (a file mode, 664, had been applied to the folder during a deploy). Nginx could read the names inside (`r`) but not enter the folder (`x`). The capital **`S`** means setgid **without** `x`.

**Solution:** separate rights for folders and files, as designed in S1.2:

```bash
sudo find /srv/navmarket -type d -exec chmod 2775 {} +   # folders: setgid + rwx rwx r-x
sudo find /srv/navmarket -type f -exec chmod 664 {} +    # files: rw- rw- r--
```

The heartbeat confirmed the fix: `http=200` from the next check.

## What I learned

- `Restart=always` + `RestartSec` make a service self-healing; `NRestarts` counts the restarts.
- `kill -9` (SIGKILL) simulates a hard crash: the process cannot clean up or refuse.
- `DynamicUser=yes` runs a service without a real account and without root.
- A service's output goes to the journal: `journalctl -u <unit>`.
- On a **folder**, `r` lists the names and `x` lets you enter; `?????????` in `ls -l` = `r` without `x`.
- Monitoring is only useful if someone reads it: here it caught a problem nobody had seen.

## Quick questions

**What does `RestartSec=5` protect against?**
A service that fails at once would otherwise restart in a tight loop; 5 s gives the system air and keeps the logs readable.
