# S3.2 - A Linux router between 2 networks

**Session 3 / 24 · Networking 1** · Completed on 5 November 2026

## Goal

On `navmarket-srv01`, build two networks from the [S3.1 plan](S3.1-addressing-plan.md) and a Linux router between them, by hand, and prove what each piece changes.

```
lan-a 10.10.1.10 ──veth── router 10.10.1.1 | 10.10.2.1 ──veth── lan-b 10.10.2.10
      Lab LAN A                                                  Lab LAN B
```

**Done when:** lan-a reaches lan-b through the router, and I can show the two states that fail before it works.

## What I did (as root on srv01)

```bash
ip netns add lan-a; ip netns add router; ip netns add lan-b           # 3 isolated network stacks
ip link add veth-a type veth peer name r-a                           # virtual cable lan-a <-> router
ip link add veth-b type veth peer name r-b                           # virtual cable lan-b <-> router
ip link set veth-a netns lan-a; ip link set r-a netns router
ip link set veth-b netns lan-b; ip link set r-b netns router
ip -n lan-a  addr add 10.10.1.10/24 dev veth-a; ip -n lan-a  link set veth-a up
ip -n router addr add 10.10.1.1/24  dev r-a;    ip -n router link set r-a up
ip -n router addr add 10.10.2.1/24  dev r-b;    ip -n router link set r-b up
ip -n lan-b  addr add 10.10.2.10/24 dev veth-b; ip -n lan-b  link set veth-b up

ip -n lan-a route add default via 10.10.1.1                          # "for any other network, ask the router"
ip -n lan-b route add default via 10.10.2.1
ip netns exec router sysctl -w net.ipv4.ip_forward=1                 # allow the router to pass packets
```

A **network namespace** is a separate network stack (interfaces, addresses, routes): Docker gives one to every container. A **veth pair** is a virtual cable.

## Proof

Full outputs: [`S3.2-proofs.txt`](S3.2-proofs.txt).

| State | Result |
| --- | --- |
| no default route in lan-a | `ping: connect: Network is unreachable` |
| routes OK, forwarding off in the router | `2 packets transmitted, 0 received, 100% packet loss` |
| routes + forwarding on | `2 received, 0% packet loss` |
| path (`tracepath`) | `1: 10.10.1.1` then `2: 10.10.2.10 reached` |

## What I learned

- A machine sends directly to its own subnet and to its **gateway** for everything else; with no route, the kernel refuses at once ("unreachable").
- Linux drops packets that are not for itself unless `net.ipv4.ip_forward=1`: that one setting turns a machine into a router.
- Forwarding is set **per namespace**: the router can route while srv01 does not.
- Each router lowers the TTL by 1; `tracepath` shows every hop.

## Quick questions

**The router has routes to both networks but the ping fails. What do you check first?**
`sysctl net.ipv4.ip_forward` on the router: at `0`, it drops what it should pass.
