# S3.1 - Addressing plan for 10.10.0.0/16

**Session 3 / 24 · Networking 1** · Completed on 3 November 2026

## Goal

Give NavMarket's future network one private range, `10.10.0.0/16`, split into subnets by role, with simple rules, so every address tells what it is.

**Done when:** each zone has a subnet with its size, gateway and ranges, the subnets do not overlap, and a script proves it.

## CIDR in one table

| Prefix | Addresses | Usable hosts | Used for |
| --- | --- | --- | --- |
| `/16` | 65,536 | 65,534 | the whole NavMarket range |
| `/22` | 1,024 | 1,022 | a large zone (office) |
| `/24` | 256 | 254 | a standard zone |
| `/30` | 4 | 2 | a link between two routers |

Usable = addresses minus the **network** address (first) and the **broadcast** address (last).

## The plan

| Subnet | Zone | Gateway | Notes |
| --- | --- | --- | --- |
| `10.10.0.0/24` | Management | `10.10.0.1` | admin access, bastion |

| `10.10.40.0/24` | Monitoring | `10.10.40.1` | logs, metrics |
| `10.10.100.0/22` | Office | `10.10.100.1` | staff devices, `10.10.100.0` to `10.10.103.255` |

| `10.10.255.0/30` | Transit | - | router to router |
| everything else | Reserved | - | room to grow |

## Rules inside every /24

| Range | Use |
| --- | --- |
| `.1` | gateway (router) |
| `.2` to `.9` | network devices |
| `.10` to `.99` | servers with fixed addresses |
| `.100` to `.199` | DHCP (automatic addresses) |
| `.254` | reserved |

## Choices

- **Zones by role, with gaps** (`.10`, `.20`, `.30`): a zone can grow, and firewall rules read by subnet ("data zone accepts the app zone only").
- **Not `192.168.x.x`**: my home network and libvirt already use it; overlapping ranges break VPNs and routing.
- **Later on AWS**, another range (`10.20.0.0/16`), so the two can be connected without overlap.

## What I learned

- A prefix `/n` keeps `n` bits for the network: `/24` leaves 8 bits, so 256 addresses.
- The first address is the network, the last is the broadcast: they are not given to hosts.
- A `/22` is four `/24`s glued together: it must start on a multiple of 4 (`10.10.100.0`).
- Planning first avoids overlaps that are very hard to fix once servers use the addresses.

## Quick questions

**How many hosts fit in `10.10.100.0/22`?**
1,024 addresses minus network and broadcast: 1,022.
