# S3.3 - Annotated packet capture (ARP, ICMP, TCP)

**Session 3 / 24 · Networking 1** · Completed on 7 November 2026

## Goal

Watch, on the router's `r-a` interface ([S3.2 lab](S3.2-linux-router.md)), what really travels when lan-a talks to lan-b: ARP, then ICMP (ping), then a full TCP connection.

## What I did (as root on srv01)

```bash
ip -n lan-a neigh flush all                                          # empty lan-a's ARP cache: force a new ARP
ip netns exec router tcpdump -i r-a -n -e -l -c 30 &                 # -e: show MAC addresses too
ip netns exec lan-a ping -c1 10.10.2.10                              # ARP + ICMP
ip netns exec lan-b nc -l 8080 &                                     # a TCP server in lan-b
echo hello | ip netns exec lan-a nc -N 10.10.2.10 8080               # a TCP client in lan-a
```

## The capture, annotated

Full outputs: [`S3.3-proofs.txt`](S3.3-proofs.txt). lan-a = MAC `5e:eb:...`, router = MAC `b6:60:...`.

| # | Packet | Meaning |
| --- | --- | --- |
| 1 | `5e:eb... > ff:ff:ff:ff:ff:ff ARP Request who-has 10.10.1.1 tell 10.10.1.10` | lan-a wants to reach another network, so it needs its **gateway's MAC**: broadcast to everyone |
| 2 | `ARP Reply 10.10.1.1 is-at b6:60:6c:ec:51:f5` | the router answers directly (unicast) |
| 3 | `10.10.1.10 > 10.10.2.10: ICMP echo request` | the ping: IP to lan-b, but the Ethernet frame goes to the **router's MAC** |
| 4 | `10.10.2.10 > 10.10.1.10: ICMP echo reply` | the answer, routed back |
| 5 | `10.10.1.10.56826 > 10.10.2.10.8080: Flags [S]` | TCP **SYN**: "let's connect", from a random client port to port 8080 |
| 6 | `Flags [S.]` | **SYN-ACK**: the server accepts |
| 7 | `Flags [.]` | **ACK**: connection open (3-way handshake done) |
| 8 | `Flags [P.] seq 1:7, length 6` | the data: `hello\n`, 6 bytes (tcpdump labels it "HTTP" only because of port 8080) |
| 9 | `Flags [.] ack 7` | the server confirms it received bytes 1 to 6 |
| 10 to 12 | `[F.]`, `[F.]`, `[.]` | **FIN** both ways, then a last ACK: clean close |

The server printed `hello`: the message crossed the router intact.

## What I learned

- **ARP** works only inside one network: to leave it, a machine asks for the **gateway's** MAC, never the final destination's.
- The **IP** addresses stay the same end to end; the **MAC** addresses change at each hop.
- **TCP** opens with SYN, SYN-ACK, ACK, numbers every byte (`seq`/`ack`) and closes with FIN; **ICMP** has no ports and no connection.
- `tcpdump -n -e` (no name lookup, with MACs), `-w file.pcap` to save for Wireshark.

## Quick questions

**Why does lan-a ask for 10.10.1.1's MAC and not 10.10.2.10's?**
10.10.2.10 is on another network: the frame goes to the gateway, which forwards the packet.
