# S3.4 - NAT: the private network reaches the Internet

**Session 3 / 24 · Networking 1** · Completed on 7 November 2026

## Goal

Give the lab networks ([S3.2](S3.2-linux-router.md)) access to the Internet through `navmarket-srv01`, with NAT, and prove that without NAT it fails.

```
lan-a 10.10.1.10 ─ router ─(transit 10.10.255.0/30)─ srv01 ─ enp1s0 ─ Internet
                    10.10.255.2              10.10.255.1     NAT here
```

## What I did (as root on srv01)

```bash
ip link add up-host type veth peer name r-up; ip link set r-up netns router
ip addr add 10.10.255.1/30 dev up-host; ip link set up-host up                 # srv01 side
ip -n router addr add 10.10.255.2/30 dev r-up; ip -n router link set r-up up   # router side
ip -n router route add default via 10.10.255.1     # the router's way out
ip route add 10.10.0.0/16 via 10.10.255.2           # srv01's way back to the lab
sysctl -w net.ipv4.ip_forward=1                     # srv01 routes too

nft add table ip lab
nft 'add chain ip lab postrouting { type nat hook postrouting priority 100 ; }'
nft add rule ip lab postrouting ip saddr 10.10.0.0/16 oifname "enp1s0" masquerade
```

**Masquerade** = source NAT: packets from `10.10.0.0/16` leaving by `enp1s0` get **srv01's address** as source; srv01 remembers each connection and sends the replies back to the right lab machine.

## Proof

Full outputs: [`S3.4-proofs.txt`](S3.4-proofs.txt) (srv01's address masked as `<VM_IP>`).

- `ip netns exec lan-a ping 1.1.1.1`: `2 received, 0% packet loss`
- on `enp1s0`: `IP <VM_IP> > 1.1.1.1: ICMP echo request` and `1.1.1.1 > <VM_IP>: ICMP echo reply`: the source is **srv01**, not `10.10.1.10`
- NAT rule removed: `2 packets transmitted, 0 received, 100% packet loss`; rule restored

## What I learned

- Private addresses (RFC 1918: `10/8`, `172.16/12`, `192.168/16`) are not routed on the Internet: without NAT the request leaves but no reply can come back.
- Routing must work **both ways**: the router needs a way out, srv01 needs a route back to `10.10.0.0/16`.
- NAT is done in the `postrouting` hook: after the routing decision, just before the packet leaves.
- My home box, libvirt and Docker all do the same masquerade.
- Namespaces, `sysctl -w` and nft rules are not saved: the lab disappears at reboot.

## Quick questions

**Why does the ping fail when the NAT rule is removed?**
The packet reaches the Internet with source `10.10.1.10`, a private address nobody can route back to.
