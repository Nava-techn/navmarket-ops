# S1.5 (Oracle) - Getting a free Oracle Cloud server when there is "no capacity"

**Session 1 / 24 · Linux 1: using it** · Started on 10 October 2026 · Completed on 21 October 2026

## Goal

Lab S1.5 needs a **public server**: `navmarket-vps01`, on the **Oracle Cloud Always Free** tier. Oracle refused to create it again and again because it had no free servers left in my region. While I used a Cloudflare Tunnel as plan B ([S1.5](S1.5-cloudflare-tunnel.md)), I automated the creation so the server is created **by itself**, as soon as Oracle has room.

**Done when:**

1. the Oracle CLI is installed and can talk to my account with an API key;
2. the network is ready: a virtual network with a public subnet;
3. a script retries the creation every 5 minutes and stops by itself after success;
4. the script can run as a systemd service, started by hand or at every boot;
5. `navmarket-vps01` exists and I can connect to it over SSH.

## Why this is needed

Oracle's **Always Free** tier gives two kinds of free servers ("shapes"):

| Shape | Processor | Free limit |
| --- | --- | --- |
| `VM.Standard.E2.1.Micro` | AMD, x86_64 | 2 small servers (1/8 CPU, 1 GB RAM each) |
| `VM.Standard.A1.Flex` | ARM (Ampere), aarch64 | 4 CPUs and 24 GB RAM in total, split as I want |

These servers are real machines shared by many free users. My **home region** is **France Central (Paris)**, and free servers can only be created there. Paris has a single data centre (one *availability domain*), so when it is full, there is nowhere else to go. Oracle's answer is then `Out of host capacity`, and its FAQ says to try again later.

Trying again by hand in the console, many times a day, is slow and boring. A script can do it for me.

## How it works

```
My workstation (always on, or at least often on)
│
├── systemd user service      → starts the script at every boot
└── retry-launch.sh           → every 5 minutes:
        │
        │  1. "Does navmarket-vps01 already exist?"   yes → stop
        │  2. oci compute instance launch (A1, then E2)
        ▼
   Oracle Cloud API (HTTPS, signed with my API key)
        │
        ├── "Out of host capacity"  → wait 5 minutes, try again
        ├── other error             → stop and show the error (a mistake to fix)
        └── success                 → stop, desktop notification
```

- The **OCI CLI** (`oci`) is Oracle's command-line tool. It calls the same API as the web console.
- Each request is **signed** with my **API private key**. Oracle checks the signature with the public key I registered in my profile. This is the same idea as SSH keys, but for HTTPS requests.
- The script only retries when the error is "no capacity" (or "too many requests"). Any other error means something is wrong in my settings, so retrying forever would be useless.

## The network

A cloud server needs a network around it before it can exist. I created it once in the console with **Networking → Virtual cloud networks → Start VCN Wizard → Create VCN with Internet Connectivity**, named `navmarket-vcn`.

| Part | What it is | Why I need it |
| --- | --- | --- |
| **VCN** (Virtual Cloud Network) | My private network inside Oracle, with its own address range | Every server lives in a network |
| **Public subnet** | A part of the VCN whose servers can get a public IP | `navmarket-vps01` must be reachable from the Internet |
| **Internet gateway** | The door between the VCN and the Internet | Without it, no traffic in or out |
| **Route table** | The rule "everything not local (`0.0.0.0/0`) goes through the Internet gateway" | Tells packets which way to go |
| **Security list** | A firewall in front of the subnet. By default it allows SSH (port 22) | Will need port 80 for the storefront |
| **Public IP** | The address visitors will use | Given at creation with `--assign-public-ip true` |

There are **two firewalls** on Oracle: the **security list** (in the cloud, in front of the server) and **iptables** (inside Oracle's Ubuntu images). A port must be open in both. This is the next part of the lab, once the server exists.

## What I did

### 1. A private working folder

```bash
mkdir -p ~/oci-retry && chmod 700 ~/oci-retry
```

The real IDs and my copy of the script live here, **outside the repository**. `700` = only my user can enter it.

### 2. Install the OCI CLI

```bash
sudo apt install pipx
pipx install oci-cli      # installs the CLI and its Python libraries in an isolated environment
pipx ensurepath           # adds ~/.local/bin to my PATH (open a new terminal after)
oci --version
```

`pipx` keeps the CLI separate from the system's Python packages, so an update of one cannot break the other.

### 3. Create and register an API key

I copied two IDs from the console: my **user OCID** (Profile → My profile) and my **tenancy OCID** (Profile → Tenancy). An **OCID** is Oracle's unique ID for every object: user, network, image, server.

```bash
oci setup config          # asks for the two OCIDs, the region (eu-paris-1), and creates a key pair in ~/.oci/
cat ~/.oci/oci_api_key_public.pem
```

I pasted the **public** key in Profile → My profile → API keys → **Add API key** → *Paste a public key*. Then:

```bash
chmod 600 ~/.oci/config ~/.oci/oci_api_key.pem    # private: only my user can read them
oci iam availability-domain list                   # test: lists my availability domain
```

The API key is **not** my SSH key: the API key proves who I am **to Oracle's API**, the SSH key will prove who I am **to the server**.

### 4. Collect the IDs the launch command needs

```bash
source ~/oci-retry/navmarket.env     # the compartment ID is already there

# the public subnet
oci network subnet list -c "$COMPARTMENT_ID" \
  --query 'data[].{name:"display-name",id:id}' --output table

# Ubuntu images compatible with the A1 shape (ARM)
oci compute image list -c "$COMPARTMENT_ID" --operating-system "Canonical Ubuntu" \
  --shape VM.Standard.A1.Flex --query 'data[].{name:"display-name",id:id}' --output table
```

- `-c` is the **compartment**, a folder for cloud resources. The root compartment has the same OCID as the tenancy.
- `--query` (JMESPath) keeps only the name and ID of each result, and `--output table` prints them as a table.
- `--shape` returns only the images that **work** with that shape (see problem 1).

I wrote the values in `~/oci-retry/navmarket.env` (template: [`scripts/oracle/navmarket.env.example`](../../scripts/oracle/navmarket.env.example)), then `chmod 600` on it.

### 5. One manual launch

```bash
oci compute instance launch \
  --compartment-id "$COMPARTMENT_ID" \
  --availability-domain "$AD" \
  --subnet-id "$SUBNET_ID" \
  --shape VM.Standard.A1.Flex --shape-config '{"ocpus":1,"memoryInGBs":6}' \
  --image-id "$IMAGE_A1" \
  --display-name navmarket-vps01 \
  --assign-public-ip true \
  --ssh-authorized-keys-file ~/.ssh/navmarket_vps.pub
```

| Option | Meaning |
| --- | --- |
| `--shape-config` | A1 is "Flex": I choose the CPUs and RAM. A small request (1 CPU, 6 GB) has a better chance to find room, and it can be resized later up to 4 CPUs / 24 GB |
| `--assign-public-ip true` | The server gets a public address |
| `--ssh-authorized-keys-file` | My SSH **public** key is copied into the server, so I can log in with my private key |

The answer `Out of host capacity` proves that the command and all the IDs are correct: Oracle only lacks room.

### 6. The retry script

Full script: [`scripts/oracle/retry-launch.sh`](../../scripts/oracle/retry-launch.sh). The important parts:

```bash
source "$ENV_FILE"                 # loads my private settings: the script itself contains no account data

# Safety first: count the instances with this name that are not terminated
count=$(oci compute instance list -c "$COMPARTMENT_ID" --display-name "$NAME" \
  --query "length(data[?\"lifecycle-state\"!='TERMINATED'])" --raw-output)
[ "$count" != "0" ] && exit 0      # already created: never make a second one

if out=$(launch VM.Standard.A1.Flex "$IMAGE_A1" '{"ocpus":1,"memoryInGBs":6}'); then success A1; fi
check "$out" A1                    # "capacity" → wait and retry; anything else → stop
```

- **Configuration separated from code:** the IDs are in a `.env` file loaded with `source`. The script can be public; the `.env` file stays private.
- `if out=$(command); then` runs the command, saves its output in `out`, and tests its **exit code** (0 = success).
- **Wait 5 minutes** between rounds. Calling the API every second would be rude and would get `429 TooManyRequests`.
- A1 first (much more powerful), then E2 if an E2 image is set.

```bash
cp scripts/oracle/retry-launch.sh ~/oci-retry/ && chmod 700 ~/oci-retry/retry-launch.sh
```

### 7. Run it by hand

```bash
nohup ~/oci-retry/retry-launch.sh >> ~/oci-retry/retry.log 2>&1 &
tail -f ~/oci-retry/retry.log
```

- `nohup ... &` runs the script in the background, and it keeps running if I close the terminal.
- `>> retry.log 2>&1` adds normal output **and** errors to the log file.
- `tail -f` follows the log live; `Ctrl+C` stops watching, not the script. To stop the script: `pkill -f retry-launch.sh`.

### 8. Start it automatically every time the computer starts

A **systemd user service** runs a program for my user, managed by systemd like any service. Unit file: [`scripts/oracle/oci-retry-launch.service`](../../scripts/oracle/oci-retry-launch.service).

```ini
[Service]
Environment=PATH=%h/.local/bin:/usr/local/bin:/usr/bin:/bin   # so systemd finds "oci" (installed by pipx)
ExecStart=%h/oci-retry/retry-launch.sh                         # %h = my home folder
Restart=no                                                     # the script decides when to stop

[Install]
WantedBy=default.target                                        # start with my user session
```

```bash
mkdir -p ~/.config/systemd/user
cp scripts/oracle/oci-retry-launch.service ~/.config/systemd/user/
systemctl --user daemon-reload                       # systemd rereads its unit files
systemctl --user enable --now oci-retry-launch       # start now AND at every login
journalctl --user -u oci-retry-launch -f             # follow the script's messages
```

- `--user`: a service for my user only, no `sudo` needed.
- By default, user services start when I **log in**. To start them at **boot**, even before I log in: `sudo loginctl enable-linger navatech`.
- Starting at every boot is harmless: if the server already exists, the script sees it and stops at once.
- When the server exists, I turn the service off: `systemctl --user disable --now oci-retry-launch`.

### 9. When the log says "SUCCESS"

```bash
ssh -i ~/.ssh/navmarket_vps ubuntu@<PUBLIC_IP>     # the IP is shown in Compute → Instances
```

Oracle's Ubuntu images use the user `ubuntu`. Next: open port 80 in both firewalls, then serve the storefront: [S1.5 (Oracle) - storefront live](S1.5-oracle-storefront.md).

## Result

On **21 October 2026 at 13:58**, after **6 h 55 min** of retries (about 80 rounds, one every 5 minutes), Oracle accepted the request:

```
retry-launch.sh: 2026-10-21 13:57:20 A1: no capacity
retry-launch.sh: 2026-10-21 13:58:25 SUCCESS with E2
systemd: oci-retry-launch.service: Consumed 3min 18.865s CPU time over 6h 55min 35ms wall clock time, 151.3M memory peak.
```

- **A1 (ARM) was still full**; the small **E2.1.Micro** (x86, 1/8 CPU, 1 GB RAM) found a place. The fallback order of the script did its job.
- The script **stopped by itself** after the success, as designed. Waiting for almost 7 hours cost only **3 minutes of CPU**: it sleeps between rounds.
- I chose to keep the service **installed but not enabled**: I start it by hand when I need it (`systemctl --user start oci-retry-launch`), instead of at every boot.

```bash
systemctl --user disable oci-retry-launch     # no automatic start
systemctl --user start oci-retry-launch       # start it myself, when I want
journalctl --user -u oci-retry-launch -n 20 --no-pager   # read the last messages
```

## Problems and solutions

### Problem 1: the image did not match the shape

**Symptom:** the console refused my choice of the full Ubuntu 26.04 image with the `VM.Standard.E2.1.Micro` shape.

**Cause:** each image declares which shapes it supports. ARM images (`aarch64`) only run on A1, x86 images on E2, and the full Ubuntu 26.04 image was not listed as compatible with this very small shape (1/8 CPU, 1 GB RAM). The **Minimal** image is made for small servers.

**Solution:** use the **Minimal** image, and let Oracle list only compatible images with `oci compute image list --shape <SHAPE>`.

### Problem 2: "Out of host capacity"

**Symptom:** `Out of host capacity` for `VM.Standard.E2.1.Micro`, then for `VM.Standard.A1.Flex`.

**Cause:** all the free servers of the Paris region were in use, and Paris has only one availability domain, so there is no other place to try. Always Free resources can only be created in the home region, which cannot be changed.

**Solution:** a script that retries every 5 minutes and stops after success, started automatically by systemd. Meanwhile, plan B: a [Cloudflare Tunnel](S1.5-cloudflare-tunnel.md).

### Problem 3: `401 NotAuthenticated` on the first CLI command

**Symptom:** `oci iam availability-domain list` → `"code": "NotAuthenticated"`, `"status": 401`.

**Cause:** Oracle could not verify the signature of the request. It finds the public key with three values of `~/.oci/config` (`tenancy`, `user`, `fingerprint`); if the key is not registered yet, or if one of these values is wrong, there is no key to check against.

**Solution:** register the public key in My profile → API keys, wait one or two minutes, and check that the fingerprint shown in the console is the same as in `~/.oci/config`:

```bash
grep fingerprint ~/.oci/config
openssl rsa -pubout -outform DER -in ~/.oci/oci_api_key.pem | openssl md5 -c   # fingerprint of my key
```

## Security rules I followed

- No real OCIDs, IP addresses or keys in this repository: only placeholders and a `.env.example` template.
- Private files in mode `600` (`~/.oci/config`, the API key, `navmarket.env`); private folder in mode `700`.
- One SSH key dedicated to this server (`~/.ssh/navmarket_vps`), and one API key for the CLI: two keys, two jobs.
- Only Always Free shapes in the script, and I never click "Upgrade" in the console.
- The script can never create two servers: it checks first and stops after success.

## What I learned

- A free cloud tier runs on real, shared machines: "out of capacity" is normal, and a region with one data centre has no fallback.
- The web console and the CLI use the **same API**: anything I click can be scripted.
- An **API key** signs each request; Oracle checks it with `tenancy` + `user` + `fingerprint`. A 401 means "I don't know who you are", not "you are not allowed".
- Every cloud object has an ID (OCID); `--query` and `--output table` make the CLI output readable.
- A cloud server needs a network first: VCN, public subnet, Internet gateway, route table, security list.
- An image must match the shape: processor family (x86_64 or aarch64) and size.
- A good retry script: waits between tries, retries only the expected error, stops on anything else, and can never act twice.
- Separate configuration (`.env`, private) from code (script, public).
- systemd can run my own scripts as **user services**, started at login, or at boot with `loginctl enable-linger`.
- Patience can be automated: the script waited almost 7 hours for me, for 3 minutes of CPU. A fallback (E2 after A1) raises the chances.

## Quick questions

**Why does the script wait 5 minutes between tries?**
To be polite to Oracle's API. Calling it too often gets the error `429 TooManyRequests`, and capacity does not come back every second anyway.

**How can I use this to get my own free Oracle server?**
Install the OCI CLI and register an API key (steps 2 and 3), create a VCN with a public subnet, copy [`navmarket.env.example`](../../scripts/oracle/navmarket.env.example) to `~/oci-retry/navmarket.env` with your own IDs, then run [`retry-launch.sh`](../../scripts/oracle/retry-launch.sh) by hand or as the systemd service (steps 7 and 8).
