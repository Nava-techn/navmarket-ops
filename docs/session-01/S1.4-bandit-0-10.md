# S1.4 — OverTheWire Bandit, levels 0 to 10

**Session 1 / 24 · Linux 1: using it** · Completed on 9 October 2026

## The game

[**Bandit**](https://overthewire.org/wargames/bandit/) is a free "wargame" by the OverTheWire community, built to teach the Linux command line to beginners. Each level is an account on a remote Linux server, reached over **SSH**. Somewhere on that server, the password for the next level is hidden: in a file with a strange name, in a hidden file, in a file with specific properties somewhere on the disk, or inside a large text file. To find it, you only have the shell and the `man` pages.

Each level's page gives the goal and a list of "commands you may need". The password found on level N opens the account `bandit(N+1)`.

**Why it matters for DevOps:** finding a file, reading the right one, filtering logs and decoding data are daily tasks on a server. Bandit trains exactly those reflexes, under the same conditions: SSH, no graphical interface, read the documentation.

| Item | Value |
| --- | --- |
| Host | `bandit.labs.overthewire.org` |
| Port | `2220` (not the default SSH port 22) |
| First account | `bandit0` / `bandit0` |
| Result | Levels **0 → 10** completed: password for `bandit11` found |

```bash
ssh -p 2220 bandit0@bandit.labs.overthewire.org   # -p: connect to a non-standard port
```

> **No passwords in this write-up.** They are kept in a private file outside the repository (`chmod 600`), as the OverTheWire rules ask players not to publish solutions. Only the commands and the reasoning are documented here.

## Level by level

### Level 0 → 1: first connection

```bash
ssh -p 2220 bandit0@bandit.labs.overthewire.org
ls                     # readme
cat readme             # the password for bandit1
```

**Why it works:** the game server listens on port 2220, so `-p 2220` is required. The password is in a plain file in the home directory.

### Level 1 → 2: a file called `-`

```bash
cat ./-
```

**Why it works:** for most commands, an argument starting with `-` is an **option**, and a lone `-` often means "standard input". `cat -` waits for keyboard input. Writing `./-` turns it into a **path** (the file `-` in the current directory), so `cat` opens the file.

### Level 2 → 3: spaces and dashes in the name

```bash
cat ./"--spaces in this filename--"
```

**Why it works:** without quotes, the shell splits the name into several arguments at each space (the same trap as the `touch` mistake in S1.2). The quotes keep it as **one** argument, and `./` stops `cat` from reading `--spaces…` as an option.

### Level 3 → 4: a hidden file

```bash
cd inhere
ls -a                  # .  ..  ...Hiding-From-You
cat ...Hiding-From-You
```

**Why it works:** on Linux, any name starting with `.` is hidden from a plain `ls`. `-a` (all) shows them. Here the name even starts with three dots to look like `..`.

### Level 4 → 5: the only human-readable file

```bash
cd inhere
ls                     # -file00 … -file09
file ./-file*          # ./-file07: ASCII text, the others are "data"
cat ./-file07
```

**Why it works:** `file` looks at a file's **content** (its "magic numbers"), not at its name, and reports its type. Only one file is `ASCII text`. Running `file` on all of them at once with the glob `./-file*` is faster than testing them one by one.

### Level 5 → 6: a file with three properties

```bash
find . -type f -size 1033c ! -executable
cat ./inhere/maybehere07/.file2
```

**Why it works:** among dozens of files in many folders, the target is human-readable, **1033 bytes**, and **not executable**. `find` combines conditions with an implicit AND:

- `-type f`: regular files only;
- `-size 1033c`: exactly 1033 bytes (`c` = bytes; without it, the unit is 512-byte blocks);
- `! -executable`: the `!` negates the test.

### Level 6 → 7: a file somewhere on the server

```bash
find / -type f -user bandit7 -group bandit6 -size 33c 2>/dev/null
cat /var/lib/dpkg/info/bandit7.password
```

**Why it works:** the file can be anywhere, so the search starts at `/`. It is owned by user `bandit7`, belongs to group `bandit6` and is 33 bytes. Searching the whole disk as a normal user produces hundreds of `Permission denied` messages. They are written to **stderr** (channel 2), and `2>/dev/null` sends them to the "black hole" device, so only the result remains on screen.

### Level 7 → 8: a word in a large file

```bash
grep millionth data.txt
```

**Why it works:** `grep` prints only the lines containing the pattern. The password is next to the word `millionth`, separated by a tab. (My first version was `cat data.txt | grep millionth`; it works, but `grep` can read the file directly, without an extra `cat` process.)

### Level 8 → 9: the only unique line

```bash
sort data.txt | uniq -u
```

**Why it works:** `uniq` only compares **adjacent** lines, so the file must be **sorted** first; identical lines then end up next to each other. `uniq -u` prints only the lines that appear exactly once. The pipe `|` sends the output of `sort` into `uniq`.

### Level 9 → 10: text hidden in binary data

```bash
strings data.txt | grep "=="
```

**Why it works:** `data.txt` is mostly binary. `strings` extracts only the sequences of printable characters, and `grep "=="` keeps the lines marked with several `=` signs, as the level's goal describes. The password is on the line `========== <password>`.

### Level 10 → 11: base64

```bash
base64 -d data.txt
```

**Why it works:** the file is **base64-encoded**: binary or text data written with only 64 safe characters. `-d` decodes it. Base64 is an **encoding**, not encryption: anyone can decode it without a key. That is why a base64 string in a config file or a Kubernetes Secret is **not** protected.

## What I learned

- Connect over SSH to a non-standard port with `-p`.
- Names that start with `-`, contain spaces, or start with `.` need `./`, quotes or `ls -a`.
- `file` tells the real type of a file from its content, not its name.
- `find` searches by type, size, permissions, owner and group, and conditions can be combined or negated with `!`.
- `2>/dev/null` hides error messages (stderr) and keeps the useful output (stdout).
- Pipes chain small tools: `sort | uniq -u`, `strings | grep`.
- `uniq` needs sorted input.
- Base64 is reversible by anyone: never treat it as a way to hide a secret.
- Method: read the level's goal, then the `man` page of each suggested command, before typing anything.
